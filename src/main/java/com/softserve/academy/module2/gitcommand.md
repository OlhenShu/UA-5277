# Команди Git та їх опис

## Базові команди

| Команда | Опис |
|---|---|
| `git init` | Ініціалізує новий Git-репозиторій у поточній директорії. |
| `git clone <url>` | Клонує (копіює) віддалений репозиторій на локальний комп'ютер. |
| `git status` | Показує поточний стан робочої директорії: які файли змінені, додані чи не відстежуються. |
| `git add <файл>` | Додає зміни у файлі до індексу (staging area) для наступного коміту. |
| `git add .` | Додає всі змінені та нові файли до індексу. |
| `git commit -m "повідомлення"` | Зберігає зміни з індексу у вигляді нового коміту з описом. |
| `git push` | Відправляє локальні коміти у віддалений репозиторій. |
| `git pull` | Отримує зміни з віддаленого репозиторію та об'єднує їх з локальною гілкою. |
| `git fetch` | Завантажує зміни з віддаленого репозиторію, але не об'єднує їх автоматично. |
| `git branch` | Показує список гілок. `git branch <назва>` — створює нову гілку. |
| `git checkout <гілка>` | Перемикається на вказану гілку. |
| `git checkout -b <гілка>` | Створює нову гілку та одразу перемикається на неї. |
| `git switch <гілка>` | Сучасна альтернатива `checkout` для перемикання між гілками. |
| `git merge <гілка>` | Зливає вказану гілку з поточною. |
| `git log` | Показує історію комітів. |
| `git diff` | Показує відмінності між поточними змінами та останнім комітом. |

## Розширені команди

| Команда | Опис |
|---|---|
| `git reset --soft <коміт>` | Скасовує коміти, але залишає зміни в індексі (staged). |
| `git reset --mixed <коміт>` | Скасовує коміти й індекс, але залишає зміни у робочій директорії (типова поведінка `git reset`). |
| `git reset --hard <коміт>` | Повністю скасовує коміти і всі зміни — небезпечна, незворотна операція. |
| `git revert <коміт>` | Створює новий коміт, що скасовує зміни вказаного коміту, не змінюючи історію. |
| `git rebase <гілка>` | Переносить коміти поточної гілки поверх іншої, роблячи історію лінійною. |
| `git rebase -i HEAD~n` | Інтерактивний rebase — дозволяє редагувати, об'єднувати (squash) чи видаляти останні n комітів. |
| `git cherry-pick <коміт>` | Переносить окремий коміт з іншої гілки у поточну. |
| `git stash` | Тимчасово зберігає незакомічені зміни, щоб очистити робочу директорію. |
| `git stash pop` | Повертає останні збережені зміни зі stash назад у робочу директорію. |
| `git stash list` | Показує список усіх збережених stash. |
| `git remote -v` | Показує список віддалених репозиторіїв, підключених до проєкту. |
| `git remote add <ім'я> <url>` | Додає новий віддалений репозиторій. |
| `git rm <файл>` | Видаляє файл із робочої директорії та індексу. |
| `git mv <старий> <новий>` | Перейменовує або переміщує файл, зберігаючи це в історії Git. |
| `git tag <назва>` | Створює мітку (тег) для позначення певного коміту (наприклад, версії релізу). |
| `git log --oneline --graph --all` | Показує компактну графічну історію комітів для всіх гілок. |

## Рідко потрібні, але корисні команди

| Команда | Опис |
|---|---|
| `git blame <файл>` | Показує, хто і в якому коміті востаннє змінював кожен рядок файлу. |
| `git bisect` | Бінарний пошук коміту, який спричинив баг, шляхом почергового тестування комітів. |
| `git reflog` | Показує історію переміщень HEAD — допомагає відновити "втрачені" коміти після reset. |
| `git clean -fd` | Видаляє невідстежувані файли та директорії з робочої директорії. |
| `git worktree add <шлях> <гілка>` | Створює окрему робочу директорію для іншої гілки без переключення поточної. |
| `git submodule add <url>` | Додає інший репозиторій як підмодуль у поточний проєкт. |
| `git archive` | Створює архів (zip/tar) вмісту репозиторію на певний коміт без історії Git. |
| `git shortlog -sn` | Показує список авторів комітів, відсортований за кількістю комітів. |
| `git show <коміт>` | Показує деталі та зміни конкретного коміту. |
| `git config --global <ключ> <значення>` | Налаштовує глобальні параметри Git (ім'я, email, alias тощо). |

## Стандартний флоу: push у власну гілку та Pull Request

1. **Оновити локальну `main`/`master`**, щоб працювати на основі найсвіжішого коду:
   ```
   git checkout main
   git pull
   ```

2. **Створити нову гілку** для своєї задачі (naming — наприклад `feature/назва`, `fix/назва`):
   ```
   git checkout -b feature/my-feature
   ```

3. **Внести зміни в коді**, після чого перевірити статус і додати файли до індексу:
   ```
   git status
   git add .
   ```

4. **Закомітити зміни** зі зрозумілим описом:
   ```
   git commit -m "Опис зробленої зміни"
   ```

5. **Відправити гілку у віддалений репозиторій** (перший push для нової гілки задає upstream):
   ```
   git push -u origin feature/my-feature
   ```
   Наступні пуші в цю ж гілку можна робити просто `git push`.

6. **Перед тим як створювати Pull Request, синхронізуватись з `main`**, щоб уникнути конфліктів:
   ```
   git checkout main
   git pull
   git checkout feature/my-feature
   git merge main
   ```
   (або `git rebase main`, якщо команда використовує лінійну історію)

7. **Створити Pull Request (PR)** на GitHub/GitLab/Bitbucket:
   - Відкрити віддалений репозиторій у веб-інтерфейсі.
   - Вибрати опцію "New Pull Request" / "Create Merge Request".
   - Вказати гілку-джерело (`feature/my-feature`) та цільову гілку (`main`).
   - Додати опис змін, за потреби прикріпити задачу/issue.
   - Призначити рев'юерів (reviewers).

8. **Пройти код-рев'ю**: відповісти на коментарі, за потреби внести правки, закомітити та запушити їх у ту саму гілку — PR оновиться автоматично:
   ```
   git add .
   git commit -m "Виправлення за коментарями рев'ю"
   git push
   ```

9. **Після схвалення (approve) — злити PR** у `main` (зазвичай через кнопку "Merge" у веб-інтерфейсі, опції: merge commit, squash, rebase).

10. **Прибрати за собою**: видалити відпрацьовану гілку локально та віддалено:
    ```
    git branch -d feature/my-feature
    git push origin --delete feature/my-feature
    ```
